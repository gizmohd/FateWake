# Admin generation dashboard and AI accounting

`/admin` is a read-only operational dashboard. All `/api/admin` routes require the persisted Admin role. UI links use the protected account cookie role, while API claims transformation replaces incoming roles with the canonical stored role. Responses omit prompts, credentials, raw provider responses, execution payloads, and raw exception details.

The dashboard reports image jobs, master asset versions, distinct assets, and completed jobs which reused a cached master. PNG/WebP derivatives are not counted as images. Job dates use creation time; image dates use asset creation time; AI request dates use attempt start time. Job status filters apply to job/image views, AI outcome filters to AI accounting. Shared artwork is attributed to the first account/survivor which queued the job, not every subsequent viewer. Existing jobs without attribution remain explicitly unknown.

Every external AI integration must adopt `IAiUsageRecorder`. OpenAI, local compatible image providers, and ComfyUI are instrumented. A durable attempt is created before the provider operation. Usage and provider request identity are saved before decoding image data. ComfyUI submission identity is saved before polling; polling, downloads, encoding, and cache hits are not AI attempts. Cancellation and timeout remain distinct outcomes. An attempt without recorded completion remains unknown/in progress rather than being marked successful.

The ledger stores nullable input/output/total/cached tokens, text/image breakdowns, credits, compute seconds, actual cost and currency. Only allowlisted provider-reported measurements are accepted. Missing data is not zero. Costs are grouped by currency; credit amounts are never converted to tokens or dollars. No price estimation or account-balance inference is used. The compatible `usage` parser handles standard token counters and optional explicitly reported credit/compute/cost fields; providers that do not return them display unavailable.

Provider plus attempt key deduplicates repeated attempt persistence. Provider execution identity owns one accounting record; repeated reports update that record instead of incrementing consumption. Additional attempts remain visible but point to the accounting owner and carry no duplicate counters. Retries with distinct provider executions remain distinct consumption. When no provider identity is reported, measurements are attributed to that individual attempt. Provider-reported identity is also copied to the artwork provenance record as soon as available.

PostgreSQL performs aggregation, filtering and bounded pagination. Year/month/day expansion uses explicit IANA timezone boundaries; individual requests can be sorted by user, date, provider, model, outcome, tokens or duration. Account search returns at most fifty labels; guest/unattributed activity has its own filter. The default timezone is America/New_York, with UTC available in the UI. The UI refreshes every fifteen seconds, retains prior successful results on failure, and reloads only expanded calendar nodes.

The migration records the tracking start independently of the first call. Prior generation records are preserved and counted as untracked when they lack ledger linkage; no token usage is backfilled or invented. The existing freeform interpreter is a deterministic mapper, not an external AI invocation. Future text, audio or other AI integrations must use the same recorder and can introduce additional operation labels.
